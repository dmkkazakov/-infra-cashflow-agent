# Проверка версии 0.1.3

Дата: 24 октября 2026 года. Автор проекта: Дмитрий Казаков.

Проверены расчёты, входные данные, оба режима harness, восстановление после ошибок, установка пакета и материалы публикации. Исправления вошли в версию 0.1.3. Числа опубликованного эксперимента сохранились.

## Исправленные ошибки

### Расчёты и данные

При очень больших, но конечных входных значениях промежуточная арифметика могла переполниться. Прямой вызов прогноза или backtest теперь возвращает понятную ошибку вместо NaN, бесконечности или ложного нулевого показателя ошибки.

Задержка сценария у нижней границы допустимого календаря могла попытаться создать месяц до 1900 года. Теперь сначала проверяется, относится ли сдвинутый месяц к будущему. Если нет, используется нулевой поток.

Убраны фиксированные денежные допуски, которые разрешали крошечный платёж при нулевом долге или выборку из нулевого лимита. Любая положительная выборка после окончания доступности кредита отклоняется. При полном погашении допускается только ограниченная погрешность машинного округления производного остатка. Сами фактические платежи и выборки не изменяются. Проверено также продолжение истории после 599 платежей по 0,1 с последним платежом отдельным вызовом.

### Harness и подключение модели

- Неверно записанный API-ключ, например с переводом строки, отклоняется до HTTP-запроса. Текст ключа не попадает в сообщение об ошибке. Проверка выполнена на искусственном ключе.
- Повтор на том же экземпляре после временного сбоя очищает состояние предыдущей попытки. Изменение входов или параметров требует нового экземпляра и нового идентификатора запуска.
- Конфигурация сценариев и возвращённый отчёт больше не разделяют изменяемые объекты с внешним кодом.
- Кэш принимается только при согласованных идентификаторах, составе файлов и контрольных суммах. Пустой или повреждённый manifest возвращает обычную ошибку CLI.
- Сбой записи указателя на последний результат не оставляет неудачную попытку помеченной как успешно завершённая.
- Пустая дата среза, неверные типы параметров транспорта, неположительный лимит ответа и чрезмерно вложенный JSON отклоняются явно.

## Как повторить основные проверки

После установки пакета из README:

```bash
python -m unittest discover -s tests -v
python scripts/audit_release.py --output outputs/reference-audit.json
python -m infra_cashflow demo --output outputs/check --simulations 1000 --seed 42
python scripts/audit_release.py --demo-dir outputs/check --output outputs/fresh-audit.json
python -m infra_cashflow evaluate examples/demo_project.json --output outputs/evaluation.json --min-train 12 --horizon 3
```

Первая проверка Decimal читает сохранённый эксперимент из `results/demo`. Вторая читает только что выполненный запуск из `outputs/check`. В обоих случаях метрики сверяются с опубликованным benchmark. Исторические результаты в `results/` сохраняют исходные хеши и версию 0.1.1.

## Что эта проверка не подтверждает

Точность на реальных инфраструктурных проектах ещё не измерялась. Использован синтетический проект с явно заданными режимами. В четырёх из двенадцати реализаций поправка по факту ухудшила результат относительно исходного плана.

Живая языковая модель не вызывалась. Локальный HTTP-тест проверяет передачу запросов, ограничения инструментов, расчёт и сохранение результата, но не качество решений внешней модели. Сырой массив фактов и искусственный ключ не попали в сохраняемый отчёт; в запрос передавались задача и расчётные сводки.

P10/P50/P90 и доли симуляций с дефицитом зависят от допущений модели. Их калибровка на реальных данных не проверена. Месячный DSCR не заменяет проверку ковенанта по кредитному договору.

GitHub хранит код и выполняет проверки при push или pull request. Постоянно работающий сервис, расписание загрузки фактов и подключение к учётной системе в эту публикацию не входят.
