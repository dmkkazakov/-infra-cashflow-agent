# Данные проекта

Вход: один JSON с `schema_version: "1.0"`. Месяцы имеют формат `YYYY-MM`, денежные суммы: миллионы валюты `currency`. Отрицательные компоненты, NaN, бесконечность, логические значения вместо сумм, пропуски, повторные месяцы, дублирующиеся ключи JSON и колонки CSV отклоняются. Снижения и возвраты следует предварительно преобразовать в согласованную схему денежных поступлений и выплат.

## Параметры верхнего уровня

| Поле | Смысл |
|---|---|
| `project_id` | Идентификатор проекта |
| `schema_version` | Версия формата, строго `1.0` |
| `synthetic_data` | Обязательный признак искусственных данных |
| `currency` | Одна валюта, трёхбуквенный код; конвертация валют вне модели |
| `amount_unit` | Строго `million` |
| `as_of` | Последний полностью наблюдённый месяц |
| `baseline_vintage` | Дата зафиксированного плана, не позже его первого месяца |
| `baseline` | Последовательные месяцы первоначального кассового плана |
| `actuals` | Последовательные месяцы фактических потоков от начала плана |
| `financing` | Начальные остатки и правила кредитной линии |

Фикстура для теста может содержать будущие факты после `as_of`. Они исключаются до оценки параметров и восстановления текущего остатка. Для реальной эксплуатации нужно подтверждать момент доступности каждого факта в исходной системе. Прототип не восстанавливает историю исправлений управленческой отчётности.

## Месячная строка

Все семь денежных компонентов обязательны. Нулевое значение передаётся явно.

| Поле | Смысл |
|---|---|
| `month` | Месяц получения или выплаты денег |
| `receipts` | Денежные поступления от эксплуатации/заказчика без долга и капитала |
| `capex` | Строительные и инвестиционные выплаты |
| `opex` | Операционные денежные выплаты |
| `tax` | Денежные налоговые выплаты; вводятся извне |
| `maintenance_capex` | Поддерживающие капитальные выплаты, включаемые в принятую модель CFADS |
| `equity` | Вклад собственника по заданному графику, не автоматическая компенсация дефицита |
| `principal` | Плановое погашение в baseline; подтверждённое погашение во всех строках actuals |
| `debt_draw` | Необязательная зафиксированная выборка в фактических данных |
| `interest` | Необязательная зафиксированная выплата процентов в фактических данных |

`debt_draw` и `interest` передаются парой и только в `actuals`. При их отсутствии историческое финансирование восстанавливается по правилам модели и это отражается в предупреждении. Чтобы прогноз начинался с реального остатка денег и долга, используйте подтверждённые фактические значения и сверьте восстановленный остаток с учётом.

В будущем договорном графике платёж ограничивается размером непогашенного долга. В наблюдённой истории погашение сверх долга всегда отклоняется как противоречивый ввод, в том числе при отсутствии записанных процентов и выборок. Фактический платёж автоматически не исправляется.

## Финансирование

| Поле | Смысл |
|---|---|
| `opening_cash` | Деньги на начало первого месяца |
| `opening_debt` | Долг на начало первого месяца |
| `opening_cumulative_drawn` | Совокупная историческая выборка линии до первого месяца |
| `facility_limit` | Лимит совокупной выборки невозобновляемой линии |
| `minimum_cash` | Заданный минимальный остаток ликвидности |
| `annual_interest_rate` | Номинальная годовая ставка долей единицы: `0.12` означает 12% |
| `availability_end` | Последний месяц, в котором разрешена выборка |

Процентная конвенция упрощена: ставка / 12 на долг на начало месяца. Комиссии, дневной day-count, DSRA, капитализация процентов, рефинансирование и распределение дивидендов не рассчитываются.

## Выход

Главные месячные поля: `cfads`, `free_cash_flow`, `interest`, `principal`, `debt_draw`, `closing_debt`, `unused_facility`, `closing_cash`, `funding_gap`, `dscr`. `dscr=null`, если обслуживание долга равно нулю. Остатки и потребность в финансировании должны читаться вместе с датой среза, горизонтом, сценарием и признаком синтетических данных.

Не складывайте месячные `funding_gap`: это потребности на даты, а не независимые расходы. Не объединяйте P10 по разным статьям в бухгалтерский баланс: покомпонентные квантили могут относиться к разным траекториям.
