# Infra Cashflow Agent

[Русский](README.md) | [English](README.en.md)

Прогноз месячного денежного потока инфраструктурного проекта: поступления, расходы, обслуживание долга и потребность в финансировании.

Проект может хорошо зарабатывать за весь срок жизни и остаться без денег посреди стройки. Подрядчик, к сожалению, не принимает оплату положительным NPV. Поэтому здесь важен каждый месяц, а не только итоговая сумма.

**Дмитрий Казаков · версия 0.1.3**

В репозитории код, синтетический проект, результаты расчётов и статьи с разбором метода. Это исследовательский прототип; на реальных проектах точность пока не проверялась.

## Быстрый запуск

Нужны Git и Python 3.10+. NumPy установится вместе с пакетом:

```bash
git clone https://github.com/dmkkazakov/-infra-cashflow-agent.git infra-cashflow-agent
cd infra-cashflow-agent
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m infra_cashflow demo --output outputs/demo --simulations 1000 --seed 42
```

В Windows, если используете `cmd`, команда активации: `.venv\Scripts\activate.bat`.

Демо работает локально, без ключа языковой модели. В `outputs/demo/latest.json` указан каталог последнего успешного запуска. Внутри находятся отчёт, помесячные CSV, параметры сценариев, хеши данных и журнал проверок.

Для своего проекта замените пример JSON. Формат описан в [словаре данных](docs/DATA_DICTIONARY.md).

```bash
python -m infra_cashflow run examples/demo_project.json --output outputs/my-run --as-of 2023-12 --horizon 36 --simulations 1000 --seed 42
```

## Что получается на примере

В демонстрационном проекте прогноз охватывает период с января 2024 года по декабрь 2028 года. Требуемый минимальный остаток денег составляет 75 млн руб.

| Сценарий | Минимальный остаток, млн руб. | Дефицит до остатка 75 млн руб., млн руб. | Остаток в конце, млн руб. |
|---|---:|---:|---:|
| Базовый | −301,23 | 376,23 | 2 178,67 |
| Неблагоприятный | −1 111,18 | 1 186,18 | −275,52 |
| Стрессовый | −2 979,18 | 3 054,18 | −2 511,79 |

У базового сценария положительный итог, но первый кассовый разрыв возникает уже в апреле 2024 года. В июне не хватает 376,23 млн руб., чтобы сохранить заданный остаток: `75 − (−301,23) = 376,23`. Месячные значения дефицита нельзя складывать: это остатки, а не отдельные платежи.

![Прогноз остатка денежных средств на синтетическом проекте](docs/publications/figures/forecast_ru.png)

Отрицательный расчётный остаток означает, что предусмотренного финансирования недостаточно. Дополнительный кредит или капитал модель сама не добавляет. Подробные результаты сохранены в [results/demo](results/demo).

## Зачем здесь harness

Все об этом говорят, и я решил попробовать.

Harness управляет расчётными инструментами: проверяет входные данные, запускает сценарии, сверяет баланс и сохраняет результат. Он ограничивает набор действий и число вызовов модели. Обязательные проверки нельзя отменить просьбой в тексте задачи.

В обычном режиме порядок действий задан заранее. Выполняются три сценария и четыре отдельных расчёта чувствительности: задержка, CAPEX, поступления и ставка. В режиме LLM языковая модель выбирает дополнительные диагностические действия из разрешённого набора. Деньги в обоих режимах считает Python.

Основа прогноза состоит из трёх частей:

1. **План проекта.** Помесячные поступления, строительный CAPEX, OPEX, денежные налоги и поддерживающий CAPEX.
2. **Поправка по факту.** Отклонения прошлых месяцев корректируют будущие компоненты плана. При небольшой истории поправка ближе к единице.
3. **Кассовая модель.** Проценты, погашение и выборка по кредитной линии переводят поток до финансирования в остаток денег.

Симуляции дают P10/P50/P90 остатка при выбранных допущениях. Эти интервалы пока не откалиброваны на реальных данных, а доля симуляций с дефицитом не является вероятностью дефолта.

## Как устроен расчёт

Все суммы заданы в миллионах одной валюты. В примере это рубли. Поступления и платежи учитываются по датам оплаты; начисленная выручка и расходы в расчёт не входят.

```text
CFADS = receipts - opex - tax - maintenance_capex
FCF   = CFADS - capex
closing_cash = opening_cash + FCF + equity + debt_draw - interest - principal
closing_debt = opening_debt + debt_draw - principal
```

Из CFADS не вычитается дополнительное изменение оборотного капитала: при кассовом вводе это повторно учло бы разницу между начислением и оплатой.

Проценты начисляются на долг на начало месяца по годовой ставке, делённой на 12. Новая выборка начинает приносить проценты со следующего месяца. Лимит невозобновляемый: погашение не восстанавливает доступную сумму. После даты окончания доступности новые выборки запрещены.

Задержка в сценарии сдвигает весь оставшийся график строительства и эксплуатации. Даты взносов капитала, погашений и окончания доступности кредита остаются прежними. Будущий нулевой поток модель не превращает в новый платёж. Месячный DSCR служит диагностикой; для проверки ковенанта нужны определения и период из кредитного договора.

Остальные допущения и ограничения собраны в [описании модели](docs/MODEL_CARD.md).

## Проверка качества и расчётов

Эксперимент использует 12 реализаций одного синтетического проекта, 840 дат прогноза и 2 520 прогнозов на один, два и три месяца вперёд. Оценивается свободный денежный поток до финансирования. Каждая дата использует только предшествующие факты.

| Метод | MAE, млн руб. | RMSE, млн руб. |
|---|---:|---:|
| Исходный план | 20,68 | 25,11 |
| Последнее наблюдение | 24,37 | 41,43 |
| План с поправкой | 10,29 | 13,75 |

Поправка улучшила результат в восьми случаях из двенадцати. Во всех четырёх случаях несмещённого плана она оказалась хуже. Такой эксперимент показывает поведение метода в заданных условиях, но не подтверждает его точность на других проектах. Вклад языковой модели в качество прогноза здесь не измерялся.

В версии 0.1.3 пройдены 96 тестов. Семь центральных сценариев и метрики всех 12 реализаций пересчитаны независимым скриптом на `Decimal`. Он не вызывает финансовое ядро или harness. Дополнительно проверены 200 случайных конфигураций денежного потока. [Разбор расчётных исправлений](docs/CALCULATION_REVIEW.md), [результат пересчёта](results/independent_audit.json) и [полный отчёт о проверке версии 0.1.3](docs/VERIFICATION.md) включены в репозиторий.

Эталонные результаты в `results/` сохранены для версии 0.1.1. Версия 0.1.3 исправляет обработку некорректных входов, крайних численных значений и сбоев агента. Финансовые допущения и числа опубликованного эксперимента не изменились. Подробности в [истории изменений](CHANGELOG.md).

Полное воспроизведение расчётов из статей:

```bash
python -m unittest discover -s tests -v
python scripts/generate_demo.py --output outputs/reproduction/demo_project.json --benchmark --benchmark-output outputs/reproduction/benchmark.json
python -m infra_cashflow demo --output outputs/reproduction/demo --simulations 1000 --seed 42
python scripts/audit_release.py --demo-dir outputs/reproduction/demo --output outputs/reproduction/audit.json
python scripts/audit_randomized.py
python scripts/audit_http_harness.py
```

Новые результаты сохраняются в `outputs/reproduction` и `outputs/additional-audits`. Генератор повторяет benchmark отдельно; Decimal-проверка сверяет свежий прогноз и замороженный benchmark из `results/benchmark.json`.

Два дополнительных скрипта повторяют арифметическую проверку случайных конфигураций, сравнение backtest на девяти сочетаниях параметров и локальный HTTP-тест из пяти запросов. Они записывают результаты в `outputs/additional-audits/`. HTTP-проверка использует loopback-сервер с заданными ответами и фиктивный ключ. [Сводка и контрольные суммы скриптов](docs/verification/extra_audits_v013.json) фиксируют границы этих проверок.

По умолчанию независимая проверка читает `results/demo/latest.json`. Чтобы проверить свежий прогноз и сохранить эталонные файлы, можно использовать отдельный каталог:

```bash
python -m infra_cashflow demo --output outputs/check --simulations 1000 --seed 42
python scripts/audit_release.py --demo-dir outputs/check --output outputs/check-audit.json
```

Для оценки качества отдельного набора данных:

```bash
python -m infra_cashflow evaluate examples/demo_project.json --output outputs/evaluation.json --min-train 12 --horizon 3
```

В демо будущие факты оставлены для проверки качества. Прогноз отсекает всё после `as_of`. Для реального проекта нужны данные, которые действительно были доступны на эту дату; месяц платежа сам по себе этого не доказывает.

## Подключение языковой модели

Нужен сервер с API формата Chat Completions и поддержкой вызова инструментов. Например, для локального сервера:

```bash
export CASHFLOW_LLM_BASE_URL="http://localhost:8000/v1"
export CASHFLOW_LLM_MODEL="your-tool-capable-model"
python -m infra_cashflow run examples/demo_project.json --mode llm --allow-network --output outputs/llm-run --objective "Find the strongest liquidity risk drivers"
```

Для внешнего провайдера укажите HTTPS-адрес API и передайте ключ через `CASHFLOW_LLM_API_KEY`. HTTP разрешён только для локального адреса loopback. Сетевой доступ включается флагом `--allow-network`; провайдер получает задачу и расчётные сводки.

Адаптер проверен на имитированных ответах и в полном цикле через локальный HTTP-сервер: выбор инструмента, расчёт и сохранение отчёта. Преждевременное завершение без обязательных проверок отклоняется. Живой вызов внешней модели не выполнялся. При ошибке модели запуск завершается с ошибкой.
